# PP-503 — Delivery Notification Preferences

## Story overview
A recipient can configure notification channel, language, quiet hours, and device. This document designs a pairwise test suite and adds two risk-based tests.

## Test inputs

| Parameter | Values |
|---|---|
| Channel | SMS, Email, Push |
| Language | English, Cebuano, Filipino |
| Quiet hours | Off, 21:00–07:00, 22:00–06:00 |
| Device | Android, iOS, Web |

## Test Cases

### TC-PP503-001 — Pairwise scenario: SMS / English / Off / Android

**Preconditions:** Recipient account exists; user is signed in; relevant channel and device are available for testing.

**Test data:** Channel = `SMS`; Language = `English`; Quiet hours = `Off`; Device = `Android`.

**Test steps:**
1. Open the delivery notification preferences page.
2. Select **SMS** as the notification channel.
3. Select **English** as the language.
4. Set quiet hours to **Off**.
5. Select **Android** as the device.
6. Save the preferences.
7. Reopen or refresh the preferences page.
8. Trigger a controlled delivery-status notification and inspect the resulting notification or dispatch record.

**Expected results:**
- The selected combination is accepted and saved without a validation error.
- After reopening, the preferences show **SMS**, **English**, **Off**, and **Android**.
- The notification uses the selected **SMS** channel and **English** language, and the system applies the configured quiet-hours policy to the selected **Android** device.
- No notification is sent through an unselected channel or to an unintended device.

## Tasks

### 1. How many combinations are there in total?

There are **3 × 3 × 3 × 3 = 81** possible combinations, because each of the four parameters has three values.

### 2. Produce a pairwise (all-pairs) set. Show the table and the count.

The **nine-case table** in the “Pairwise test data” section is a complete all-pairs covering array. Every possible pair of values from any two different parameters occurs at least once. There are six parameter pairs, each with 3 × 3 = 9 value pairs; all 54 required parameter-value pairs are covered.

**Pairwise count: 9 test cases.** This is also minimal: any one pair of three-valued parameters alone has nine distinct value combinations, requiring at least nine test cases.

The table was constructed by hand using the nine (i, j) pairs for i, j ∈ {0, 1, 2}: Channel = i, Language = j, Quiet hours = (i + j) mod 3, Device = (i + 2j) mod 3, mapped to the value orders shown above.

### 3. Name two additional combinations because of risk, not coverage, and explain why.

| Additional case | Channel | Language | Quiet hours | Device | Risk justification |
|---|---|---|---|---|---|
| TC-PP503-010 | SMS | Cebuano | 22:00–06:00 | iOS | Midnight-crossing quiet hours, localized SMS text and encoding |
| TC-PP503-011 | Push | Filipino | 22:00–06:00 | Android | Android push permissions/background delivery and midnight scheduling |

These two combinations are **not in the nine-case pairwise set**. They are added to probe plausible multi-factor failures, not to fill any missing pairwise coverage.

**Total planned tests: 11 (9 pairwise + 2 risk-based).**
